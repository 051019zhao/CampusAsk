# 工程升级与验证记录

## 这一轮解决的问题

1. 官网更新不再完全依赖人工整理：增加计划抓取与候选审核，保留来源、指纹和审核记录，审核写入原知识表后进入 RAG 增量索引。
2. 向量服务中断时不再使整个问答失败：保留关键词检索、读取已有资料并可保存无向量记忆。模型配置变化时旧记忆也可按关键词召回。
3. 记忆清理从用户请求中移到独立定时维护；查询同时检查 90 天期限，过期内容即使未物理清理也不能参与回答。摘要从有效历史重建，防止旧背景残留。
4. 增加请求校验、统一的新接口错误、请求编号及日志清理；业务搜索历史和通知已读操作限定当前用户。
5. 密钥移出源代码；新密码采用随机盐 PBKDF2，旧 MD5 成功登录后通过条件更新升级；不打印密码请求对象，不返回重置后的明文密码。
6. 修复前端检查配置并清理实际发现的问题；按路由分包，新增官网采集审核页与任务状态刷新，刷新任务状态不会覆盖正在编辑的正文。
7. 增加可复制的配置示例、无示例账号的全新数据库脚本、增量建表脚本、GitHub Actions 和 PR 检查模板。

## 设计依据

- [RFC 9309 robots 访问规则](https://www.rfc-editor.org/rfc/rfc9309.html)：实现了常见规则子集，抓取失败采取保守跳过。
- [jsoup 正文选择与提取](https://jsoup.org/cookbook/extracting-data/selector-syntax)：使用配置的正文选择器，不执行网页脚本。
- [OWASP 密码存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)：采用 PBKDF2-HMAC-SHA256，600000 次迭代；随机盐与算法参数随哈希保存。

这些改动使项目更容易复现、验证和维护，不意味着已完成生产部署或完整安全认证。
